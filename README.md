# SMART LOST & FOUND

**Team Alpha NEXUS** · C++17 Campus Lost-and-Found System

## Overview

SMART LOST & FOUND is a campus item recovery application. It lets users record lost and found belongings, browse reports, and compare found items with lost reports using an explainable matching score.

## Main features

- Report a lost item or a found item
- Browse recent campus reports
- Compare found reports with lost reports
- Score possible matches using category, description keywords, location, and date
- Display reasons behind each suggested match
- Responsive interface built with HTML and CSS
- C++17 server-side application logic

## Technology stack

- **C++17** — web server, request handling, validation, and matching algorithm
- **cpp-httplib** — lightweight HTTP server library
- **CMake** — build configuration
- **HTML and CSS** — browser interface

## Requirements

- C++17-compatible compiler
- CMake 3.16 or newer
- Internet access for the first build to download cpp-httplib

## Build and run the web application

Run these commands from the repository root:

```bash
cmake -S cpp-web -B build
cmake --build build --config Release
```

Run the executable generated by CMake:

- **Windows with Visual Studio:** `build\Release\smart-lost-found-web.exe`
- **Windows with a single-configuration generator:** `build\smart-lost-found-web.exe`
- **macOS/Linux:** `./build/smart-lost-found-web`

Open **http://localhost:8080** in your browser. To use a different port, set the `PORT` environment variable before starting the program.

## Build the matching demo

From the repository root:

```bash
cmake -S cpp -B matcher-build
cmake --build matcher-build --config Release
```

Run the generated `smart-lost-found-matcher` executable from the build directory.

## Matching approach

The scoring engine considers:

| Signal | Maximum contribution |
|---|---:|
| Same category | 30 points |
| Shared description/title keywords | 35 points |
| Similar location | 20 points |
| Date proximity | 15 points |
| **Maximum score** | **100 points** |

A match score is only a suggestion to help users review reports. It is not proof of ownership.

## Current prototype limitations

- Reports are stored in server memory and are lost when the server stops.
- User accounts, persistent database storage, photo uploads, claims, and production hosting are not included in this prototype.
- The prototype is intended for demonstration and local testing. Do not expose it publicly or use it to store real personal information until persistent storage, authentication, security controls, and deployment have been implemented and tested.
